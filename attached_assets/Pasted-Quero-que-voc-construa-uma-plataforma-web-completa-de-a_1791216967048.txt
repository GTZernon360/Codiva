Quero que você construa uma plataforma web completa de aprendizado de programação, inspirada na experiência de plataformas como Duolingo, mas totalmente focada em programação.

Não quero apenas um site com textos e exercícios.

Quero uma aplicação real, com usuários, autenticação, logout, banco de dados, progresso salvo, XP, níveis, dificuldades pedagógicas, exercícios interativos, revisão, conquistas, perfil e estrutura preparada para crescer.

A plataforma deve ensinar programação desde o nível iniciante até níveis avançados.

---

O usuário deve:

* Criar uma conta

* Ter seu progresso salvo
* Aprender conceitos
* Entender por que eles existem
* Ver onde eles são utilizados
* Resolver exercícios
* Receber XP
* Subir de nível
* Manter sequência de estudos
* Revisar conteúdos antigos
* Desbloquear novas lições
* Fazer desafios
* Acompanhar estatísticas
* Evoluir gradualmente

A plataforma deve ensinar o usuário a realmente programar, e não apenas decorar sintaxe.

# 3. FILOSOFIA DE ENSINO

Antes de ensinar o usuário a fazer alguma coisa, explique POR QUE aquilo existe.

Não comece imediatamente com:

"Agora escreva este código."

Primeiro explique:

* O que é?
* Para que serve?
* Onde é utilizado?
* Por que foi criado?
* Qual problema resolve?
* Por que um programador precisa conhecer isso?
* É algo essencial?
* É algo útil, mas secundário?
* É algo que pode ser considerado desnecessário dependendo da situação?
* Quais são as alternativas?
* Quais são suas vantagens?
* Quais são suas limitações?

Depois disso:

* Mostrar exemplos
* Explicar o conceito
* Mostrar código
* Fazer exercícios

A ordem preferencial deve ser:

CONTEXTO
↓
O QUE É
↓
PARA QUE SERVE
↓
ONDE É USADO
↓
POR QUE USAR
↓
É NECESSÁRIO?
↓
EXEMPLOS
↓
EXPLICAÇÃO TÉCNICA
↓
CÓDIGO
↓
EXERCÍCIOS
↓
DESAFIO

# 4. EXEMPLOS FORA DA PROGRAMAÇÃO

As explicações não devem ficar presas exclusivamente à lógica de computadores.

Utilize analogias e situações do mundo real quando elas realmente ajudarem.

Por exemplo:

Para explicar uma variável:

"Imagine uma caixa com uma etiqueta dizendo 'idade'. Dentro dela existe um valor."

Para explicar uma condição:

"Imagine uma catraca que verifica se você tem ingresso. Se tiver, entra. Se não tiver, não entra."

Para explicar uma função:

"Imagine uma máquina de fazer suco. Você coloca frutas e ela realiza um processo para produzir o resultado."

Para explicar um banco de dados:

"Imagine um enorme arquivo organizado, onde cada ficha possui informações específicas e pode ser encontrada rapidamente."

Depois da analogia, conecte imediatamente com a programação.

Não quero analogias que compliquem mais o conceito.

A analogia deve servir como ponte para o conceito real.

# 5. EXPLICAÇÃO DAS LINGUAGENS

Não quero que HTML, CSS, JavaScript, Python, TypeScript, C#, etc. apareçam apenas como ferramentas que precisam ser utilizadas.

Cada linguagem ou tecnologia deve ser apresentada adequadamente.

Antes de começar uma nova linguagem, explique:

* O que é
* Por que existe
* Qual problema resolve
* Onde é usada
* Quem normalmente utiliza
* O que pode ser construído com ela
* Suas principais características
* Vantagens
* Limitações
* Quando faz sentido usar
* Quando não faz sentido usar
* O que diferencia essa tecnologia de outras
* Qual é sua importância no mercado e no desenvolvimento de software
* Como ela se relaciona com tecnologias aprendidas anteriormente

Por exemplo, antes de JavaScript:

Explique que HTML estrutura páginas, CSS controla apresentação e JavaScript adiciona comportamento e lógica.

Antes de TypeScript:

Explique sua relação com JavaScript e por que alguém decidiu adicionar tipagem ao ecossistema.

Antes de backend:

Explique por que o navegador sozinho não resolve determinados problemas e por que precisamos de servidores.

Antes de banco de dados:

Explique por que simplesmente guardar informações em variáveis não é suficiente para aplicações reais.

O aluno deve entender a necessidade antes de aprender a ferramenta.

# 6. IMPORTÂNCIA DOS CONCEITOS

Cada assunto pode ser classificado pedagogicamente como:

### ESSENCIAL

Conhecimento fundamental que todo programador da área deve conhecer.

### MUITO ÚTIL

Não é necessariamente obrigatório em todos os projetos, mas aparece frequentemente.

### CONTEXTUAL

Importante dependendo da área ou tecnologia.

### OPCIONAL

Pode ser útil, mas não deve receber atenção exagerada no início.

### LEGADO / HISTÓRICO

Importante entender por contexto, mas não necessariamente algo que o aluno deve utilizar atualmente.

Isso NÃO significa remover os assuntos menos importantes.

Significa explicar honestamente o peso deles.

Não quero gastar horas ensinando uma ferramenta secundária enquanto conceitos fundamentais ainda não foram dominados.

# 7. SISTEMA DE DIFICULDADE

A dificuldade NÃO determina qual nível do curso o usuário pode acessar.

Ela NÃO serve para pular módulos.

O currículo continua seguindo a progressão normal.

A dificuldade muda:

* Forma de falar
* Profundidade das explicações
* Tipo de exemplo
* Complexidade dos exercícios
* Quantidade de orientação
* Quantidade de dicas
* Tamanho das tarefas
* Quantidade de conceitos combinados
* Necessidade de raciocínio
* Necessidade de pesquisa
* Tempo esperado para resolver

Existem três níveis principais:

---

## 🟢 FÁCIL

A linguagem deve ser extremamente simples.

Imagine que estamos explicando para alguém muito jovem que nunca teve contato com programação.

Não infantilize o usuário de forma irritante, mas utilize:

* Frases simples
* Vocabulário básico
* Analogias fáceis
* Exemplos pequenos
* Poucos conceitos por vez

Os exercícios devem ser diretos.

Exemplo:

"Crie uma variável chamada `nome` e coloque seu nome dentro dela."

O objetivo é fazer o usuário entender o conceito sem sobrecarregá-lo.

---

## 🟡 MÉDIO

A linguagem deve ser natural.

O usuário já entende os fundamentos.

As explicações podem utilizar termos técnicos básicos sem precisar explicar cada palavra.

Os exemplos devem ser mais próximos de situações reais.

Os exercícios devem exigir raciocínio básico.

Exemplo:

"Crie uma função que receba uma lista de números e retorne somente aqueles que são maiores que 10."

Aqui o usuário já precisa combinar conceitos.

---

## 🔴 DIFÍCIL

A linguagem deve ser mais técnica e complexa.

O usuário deve ser tratado como alguém que já possui conhecimento da área.

Utilize:

* Terminologia técnica
* Explicações mais profundas
* Exemplos mais realistas
* Problemas menos óbvios
* Menos instruções explícitas

Os exercícios devem:

* Exigir raciocínio
* Combinar vários conceitos
* Fazer o usuário sair da zona de conforto
* Possuir múltiplas etapas
* Ser maiores
* Demorar mais para resolver
* Exigir planejamento
* Às vezes exigir pesquisa na documentação
* Fazer o usuário descobrir parte da solução sozinho

A dificuldade deve fazer o usuário pensar:

"Eu sei as ferramentas, mas preciso descobrir como combiná-las."

Não quero exercícios difíceis apenas porque possuem mais código.

Quero problemas genuinamente mais complexos.

---

# 8. EXEMPLO DE EVOLUÇÃO DA LINGUAGEM

O mesmo conceito pode ser explicado de formas diferentes.

### Fácil

"Uma variável é como uma caixinha que guarda uma informação."

### Médio

"Uma variável permite associar um nome a um valor para que possamos utilizá-lo posteriormente no programa."

### Difícil

"Uma variável representa uma referência nomeada a um valor dentro de determinado contexto de execução. Seu comportamento depende do escopo e das regras de resolução da linguagem."

A informação fundamental continua sendo a mesma.

O que muda é a profundidade e a linguagem utilizada.

---

# 9. EXEMPLOS DE EVOLUÇÃO DOS EXERCÍCIOS

## Fácil

"Crie duas variáveis, some os valores e mostre o resultado."

## Médio

"Crie uma função que receba uma lista de números e retorne a média deles."

## Difícil

"Implemente uma função responsável por processar uma coleção de valores, validar entradas inválidas, ignorar dados inconsistentes e retornar estatísticas agregadas sem modificar a coleção original."

O exercício difícil não deve simplesmente ser "o mesmo exercício com números maiores".

Ele deve exigir mais pensamento.

# REGRA MAIS IMPORTANTE

Não construa simplesmente um "site de curso".

Construa uma plataforma de aprendizagem.

O usuário deve sentir que está evoluindo como programador.

A plataforma deve ensinar primeiro o CONTEXTO e o PORQUÊ, depois o CONCEITO, depois mostrar EXEMPLOS e só então exigir que o usuário PRODUZA algo.

A dificuldade deve fazer o usuário evoluir intelectualmente, não apenas avançar números.

No fácil, quero que o usuário pense:

"Entendi."

No médio:

"Entendi, agora preciso pensar um pouco."

No difícil:

"Eu sei o que preciso usar, mas preciso descobrir como resolver isso."

O objetivo final é que, depois de passar por toda a plataforma, o usuário não apenas saiba escrever código, mas consiga olhar para um problema novo e pensar:

"Eu não sei resolver isso ainda, mas sei como descobrir."

COMECE PRIMEIRO PELA ARQUITETURA E INFRAESTRUTURA DA APLICAÇÃO. NÃO COMECE CRIANDO CENTENAS DE EXERCÍCIOS.
